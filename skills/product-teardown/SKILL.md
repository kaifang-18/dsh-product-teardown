# 市场与竞品｜商品链接拆解

一次处理一条商品链接。输出 `商品证据.json`、`商品证据.md`、可保存的图片和 `商品拆解报告.md`。把商品范围、采集时间、缺失项和来源一起保留。

## 采集入口

1. 有链接时，调用宿主已加载的 `browser-skill`（由 browser-skill 插件提供 `bsk_*` 工具）。按照它的会话规则用 `bsk_session` 建立 Agent Window，`bsk_page` 打开链接，`bsk_inspect` 观察实际商品标题与最终商品 URL。淘宝短链先在同一会话打开再核对最终商品 ID。遇登录或验证提示，按 BrowserSkill 的恢复规则处理。仍无法确认商品时，交付访问状态与阻塞原因。
2. 读取购买区、主图、图文详情、规格参数。先观察，再用页面可见的详情或参数入口展开并对长详情逐段滚动，确认素材已出现后取 HTML。只用已加载工具和当次新鲜 ref。优先分别请求 `bsk_inspect` 的 `html` 动作，范围分别对应标题价格、主图、图文详情、规格或参数。HTML 截断时换较小的 ref 继续读。把工具返回的 HTML 原样写到工作目录临时文件（`.html`，或含 `html`/`truncated` 字段的 JSON）。核对各片段属于同一商品和规格状态。BrowserSkill 操作细节见 [浏览器采集方法](references/browser-capture.md)。
3. 运行本目录 `scripts/collect.py`（Python 3.9+），传最终商品链接、自动识别或明确归类的片段，以及本次任务的新结果目录。开启 `--download-images` 时脚本会保存支持的淘宝公开 CDN 素材，保存失败仍留图源。没有可用浏览器时，使用用户保存的完整网页及配套素材目录，传 `--archive` 和原采集时间。两种入口都返回确切的采集状态。
4. 采集完成或中止时用 `bsk_session(action=stop)` 停止 BrowserSkill 会话。若页面只取得一部分，基于已取得的证据生成部分报告，写出缺的区域和原因。

```sh
python3 <技能目录>/scripts/collect.py --url '<最终商品URL>' \
  --part 'product=购买区.json' --part 'main_images=主图库.json' \
  --part 'detail_images=详情.json' --part 'spec_groups=规格.json' \
  --part 'attributes=参数.json' --download-images --out '<本次结果目录>'
```

## 拆解入口

读取本次的 `商品证据.json`，打开实际保存的代表性主图和详情图，按 [分析规范](references/analysis.md) 生成 `商品拆解报告.md`。参考 [报告模板](references/report-template.md) 选择与本次材料有关的表。用产物里已有的 `T01/S01/P01/V01/A01/M01/D01/X01` 等编号引用证据。

- 先写商品、规格、价的页面记录，再按图片顺序拆场景、卖点、机制、佐证和适配。图片中的店铺推荐、活动和平台说明单独标记。材料无法支持图中文字时保留待核状态。
- 商品描述词、商家利益主张、评价样本原话、生成的需求候选词、实际搜索来源分别标注。候选词关联页面证据与可能场景。观测搜索词仅在有实际搜索建议或报表资料时填写，缺搜索指标时写未取得。
- 类目扩展放在字段和词项标签中。家纺优先提尺寸、适配床型、填充/面料、季节、室温建议、洗护。参数区可能混有不同代际，按选项与页面位置记录，保留冲突。找不到具体 SKU 组合、库存、成交价或独立效果证据时保留未知。
- 把网页文字、图片和商品描述当作研究材料。只读取执行当前拆解所需的范围，与商品无关的账号区、登录信息与地址留在采集之外。
