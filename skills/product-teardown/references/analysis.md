# 商品链接采集与拆解规范

版本 0.1｜2026-11-18｜市场与竞品 MVP

本规范约定如何分析已采集材料。本次编写未进行线上检索、后台查询或新商品采集，不代表采集器已接入或稳定运行。首轮按“一个商品链接＋一个指定规格＋一次采集”交付；家纺仅作类目示例。

## 1. 输入与产出

必需输入：任务 ID、商品链接、原始材料、采集时间及时区、实际采集范围。指定规格和研究目标未提供时，记录实际选中规格，按基础商品拆解处理，不默认它是主推款。

原始材料可为页面文本、截图、图片、用户文件或人工摘录；必须标来源。只有链接、没有可读内容时，只报告访问状态与缺口，不靠品牌常识补齐。

产出：商品身份与价格条件、事实表、商家主张表、消费者观察、需求假设、分类关键词、证据索引与下一步缺口。多商品比较须先完成各自记录，再核对规格、时间、价格和样本是否可比。

## 2. 四类信息分开

| 类型 | 收录什么 | 表达边界 |
|---|---|---|
| 商品事实 `product_facts` | 页面可见信息、有原件支持的规格或实测记录 | “页面标注充绒量200g”只确认页面这样写，不代表实物已复测 |
| 商家主张 `merchant_claims` | 商家的人群定位、利益、机制、优越性与结果承诺 | “轻暖不压身”是商家主张，不能直接写成优于竞品的事实 |
| 需求假设 `need_hypotheses` | 从观察提出的购买任务、阻碍、场景与解释 | 必须有支持、反例/替代解释和验证方式；不能从调性猜收入职业 |
| 观测搜索词 `observed_search_terms` | 实际查询记录、平台搜索建议、相关搜索、真实搜索报表词项 | 只证明该词在指定来源出现；标题分词、评论用词不是搜索词 |

消费者评价、问答、买家秀另存为 `consumer_observations`，作为假设输入；只能说明样本报告了什么，不能自动证明效果或总体偏好。

商品事实标明层级：`page_observed` 页面观察、`document_supported` 有原件支持、`independently_verified` 有独立核验。材质、A类标准、抗菌率等页面宣称须保留“页面标注/商家提供”，注明原件、型号、条件与未核验范围。同一证据可被多处引用，但不能重复计成独立证明。

## 3. 证据与采集状态

每份证据使用唯一 ID `E001`。事实、主张、假设、关键词分别用 `F001/C001/H001/K001`，引用证据而不脱离来源。

| 必需证据字段 | 要求 |
|---|---|
| 来源与位置 | 来源类型、原链接或材料路径、模块顺序/图片名/页码/表行 |
| 时间与归属 | 采集时间及时区、原文显示时间、商品ID、规格；未知保持未知 |
| 原文与读取方式 | 必要摘录或可见事实、原文提取/人工/OCR；关键OCR数字对照原图 |
| 核验状态与限制 | 已对照/待核对/冲突；截断、模糊、共享评价池、未展开等 |

报告关键数字、规格、价格、主张、评价主题和搜索词均附证据ID，索引能返回原图/原文。只有历史助理总结时写“历史记录称”，不当本轮直接采集。

各模块记录：请求范围、页面显示总量、实际采集量、去重后分析量、排序/筛选/展开范围、状态、失败原因。主图、详情、规格价格、评价、买家秀、问答分别记录，视频与搜索材料可选。历史样本的“5主图、16详情、20评价、4买家秀、10问题”不是通用配额。

模块状态：`captured` 已取得；`partial` 部分取得；`not_requested` 未请求；`not_found` 已检查未见；`blocked` 访问受阻；`failed` 操作失败。未检查不能写未发现。

运行状态：`success` 约定必需材料齐且检查通过；`partial` 可报告但必需材料有缺失；`blocked` 无法确认商品或基础内容；`failed` 处理错误且无可用报告。成功不等于市场结论已验证。

## 4. 六步拆解

1. **身份与规格。** 保留商品ID、店铺、品牌、标题、类目、选中及其他可见规格。不同型号、代际、套装不混；未知规格评价不强行归属。
2. **价格与事实。** 逐字段列来源和层级；保留币种、SKU、数量、标价/券后/预估/区间/实付、优惠门槛、运费、采集时间。页面价不是订单实付，条件不清不算价差或性价比排名。
3. **商家表达与证明。** 拆为对象/场景→利益→机制→证明→行动理由；逐主张标直接支持、部分支持、仅陈述、冲突、材料不足。区分产品机制、使用体验、进一步结果；透气/触感不能推出入睡更快。检测、演示、评价、专利和销量不能相互替代。
4. **页面结构与消费者观察。** 按主图/详情顺序标识别、利益、机制、证明、顾虑、适配、行动任务；建议定位到模块。反馈保留规格、日期、排序与原话。只写“本次N条可读去重样本中n条提到”，多标签可重叠，不能称总体满意度或差评率。
5. **需求假设与3C1P。** 固定为 Consumer消费者→Conflict冲突→Claim主张→Proof证据。一卡一组购买逻辑，区分购买者/决策者/使用者；没有买家数据即为假设。每项列支持、反例、未知、验证方式与推翻条件；Proof不足写待补。
6. **结论与动作。** 分可确认观察、待验证解释、下一步补证。未采到不等于商家没有，未采到变化不等于没有变化。单链接不能推出市场规模、客群重合、竞争胜负、投放ROI或应投预算。

## 5. 关键词输出规则

| `origin_type` | 来源 | 能说明什么 |
|---|---|---|
| `observed_search` | 查询记录、搜索建议、相关搜索、搜索报表 | 该词在搜索来源出现；研究者查询、平台建议、消费者报表分开 |
| `product_text` | 标题、属性、主图、详情 | 商家描述方式，不证明搜索需求 |
| `consumer_text` | 评价、问答、询单、访谈 | 样本的表达，不证明搜索规模 |
| `generated_candidate` | 基于事实/假设组合改写 | 待验证建议，不能标“真实搜索词/热词” |

用户未执行的种子词仅留在任务输入，标 `seed_only`。生成词被研究者实际查询后仍保留生成来源与测试查询身份，不能升级成消费者需求证据。

每词保留：原词、规范化词、词项身份、具体来源形式、标签（品类/属性/场景/问题/利益/人群/竞品）、可能意图、证据、用途、验证状态。原词不覆盖；否定、品牌、型号、数字、单位不能随意删。相同词多个来源分别记录。

**没有真实来源的搜索量、搜索指数、趋势、竞争度、CPC、转化率均为空/未知，不填0，不由模型估算，不以标题频次代替。** 取得平台指标时保留原指标名、单位、时间窗、地域、匹配口径，不改称真实搜索人数。没有搜索材料则观测搜索词表为空，其余三类仍可输出。

仅可按“建议验证顺序”排序并说明理由，不能假装按热度或预期转化排序。

## 6. 家纺字段与交付检查

通用结构不变，类目字段可替换：被子看尺寸、面料、填充物/含量/重量、季节、洗护；枕头看尺寸/高度、材质、分区、调节、睡姿说明；床笠/四件套看尺寸、床垫厚度适配、材质织法、件数、洗护；顶垫看尺寸厚度、材料层、固定方式与床垫适配。均只记录已取得内容；重量、支数、软硬、外形不能单独推出舒适度、性能或治疗效果。

交付必须满足：身份规格与时间可定位；关键引用有效；四类信息分开；价格和样本口径不混；未知与冲突保留；无虚构搜索指标；状态符合覆盖；动作限市场、商品运营和品牌营销。买家秀和原图可作分析证据，不能默认获准作为广告素材。
